# 출력 형식 템플릿

오늘 스크럼 문서의 `## 진행 현황` 아래는 항상 이 형식을 따른다. 날짜는 오늘 날짜로 바꾼다.

```markdown
## 진행 현황 (Linear 2026.06.16 기준)
---
### ✅ 완료
- [기능태그] 항목 (어제 새로 완료된 것만, 묶어서 요약)
- ...
### 📌 이번주 마감
- [기능태그] 항목 (진행중 + 이번주 닫을 Todo)
- ...
### ❌ 취소·정리
- [기능태그] 항목 (어제 취소/보관된 것)
- ...
```

예시:

```markdown
## 진행 현황 (Linear 2026.06.16 기준)
---
### ✅ 완료
- [디자인] 메인 화면 시안 확정
- [프론트] 개발환경 셋업 (전체)
### 📌 이번주 마감
- [백엔드] 파일 업로드 API
- [프론트] 폴더 트리 컴포넌트 (목표 6/18)
### ❌ 취소·정리
- [백엔드] 레거시 동기화 잡
```

규칙

- 각 항목 맨 앞에 기능 태그를 붙인다: `[기획]` `[디자인]` `[프론트]` `[백엔드]`. 태그는 이슈의 Linear 팀에서 정한다 (`mapping.md`의 팀 ↔ 태그 표). 한 상태 섹션 안에서는 기획 → 디자인 → 프론트 → 백엔드 순으로 모은다. 팀이 매핑표에 없으면 태그 없이 두고 보고에 적는다.
- 회의에서 말하기 좋은 수준으로 단순하게. Task 번호(WEBTECH-xxxx 등)는 넣지 않는다.
- 강조나 굵게는 최소화한다. em대시는 쓰지 않는다.
- "착수", "목표 6/18" 같은 짧은 보조 표시는 백틱이나 괄호로 붙일 수 있다.
- 세 하위 섹션 중 해당 항목이 없으면 그 섹션은 빈 채로 두되 헤더는 남긴다.

`## 어제 To do`는 어제 문서의 `## 오늘 To do`를 그대로 옮긴 체크리스트 형식이다.

```markdown
## 어제 To do
---
- [x] 어제 오늘To do에 있던 항목 (체크 상태 원본 유지)
	- [x] 하위 항목
- [ ] ...
```

`## 오늘 To do`는 사람이 회의 중 직접 채운다. 스킬은 비워 두거나(이미 비어 있으면) 손대지 않는다.
